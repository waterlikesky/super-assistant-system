# 架构 v0：个人超级助理

> 状态：设计文档。M0 仅实现 schema + 假数据 ingest 演示。

---

## 1. 目标与非目标

**目标**

- 多渠道**只读**摄入 → 统一消息/事件模型 → 本地记忆 → Agent 检索增强
- 「越用越聪明」：定时摘要 → 事实抽取 → 记忆写入 → 下次问答命中
- 隐私：本地优先、脱敏、显式同意、密钥不进 git

**非目标（v0）**

- 默认开通微信/钉钉自动回复
- 云端托管用户完整聊天记录
- 一次导入「人生全部数据」

## 2. 分层

```
┌─────────────────────────────────────────────────────────┐
│  Agent 层（agent/）                                      │
│  问答 / 日报 / 提醒草稿；工具调用；出站适配器【默认禁用】   │
└──────────────────────────▲──────────────────────────────┘
                           │ 检索 facts + chunks
┌──────────────────────────┴──────────────────────────────┐
│  记忆层（memory/）                                        │
│  - facts：结构化事实（人、项目、偏好、待办）               │
│  - chunks：脱敏后的可检索片段                             │
│  - 可选：自托管 Mem0 作实现后端                           │
└──────────────────────────▲──────────────────────────────┘
                           │ 规范化事件
┌──────────────────────────┴──────────────────────────────┐
│  摄入管道（ingest/）                                      │
│  validate → redact → normalize → upsert                  │
└──────────────────────────▲──────────────────────────────┘
                           │ ChannelEvent
┌──────────────────────────┴──────────────────────────────┐
│  接入层（connectors/）只读                                │
│  email_oauth | file_export | dingtalk_api | wechat_local │
│  （wechat_local 默认关闭）                                │
└─────────────────────────────────────────────────────────┘
```

## 3. 统一事件 Schema（摘要）

完整 JSON Schema：`schemas/channel_event.schema.json`。

核心字段：

| 字段 | 含义 |
|------|------|
| `id` | 全局唯一（建议 `channel:native_id`） |
| `channel` | `email` \| `wechat` \| `dingtalk` \| `sms` \| `feishu` \| `file` |
| `direction` | `inbound`（v0 只处理） |
| `timestamp` | ISO8601 |
| `participants` | 已脱敏或哈希后的参与方 |
| `thread_id` | 会话/线程 |
| `content_text` | 纯文本（可截断） |
| `sensitivity` | `public` \| `personal` \| `confidential` |
| `consent_tag` | 用户显式同意批次 |
| `raw_ref` | 本地 raw 路径或「未持久化」标记——**禁止把 raw 推远端** |

## 4. 记忆层设计

1. **Episodic chunks**：短摘要 + embedding（本地向量库）
2. **Semantic facts**：`subject / predicate / object / source_event_ids / confidence / updated_at`
3. **写入策略**：批量 job，而非每条消息实时打满 LLM
4. **遗忘 / 覆盖**：同 subject 冲突时保留高置信或更新时间更新的事实，并留审计

「越用越聪明」闭环：

```
新事件 →（可选）滑动窗口摘要 → 事实抽取 prompt
      → memory.upsert_facts / upsert_chunks
      → Agent 问答前 memory.search(query, user_id)
```

## 5. 隐私边界（硬规则）

| 规则 | 说明 |
|------|------|
| 本地优先 | 默认可在单机跑通；云端 LLM 只接收**脱敏摘要/事实** |
| 禁止默认上传完整聊天 | 配置项 `allow_raw_llm_upload=false` 默认 |
| 密钥 | `.env` /系统钥匙串；不进 git |
| 邮件 | OAuth 最小权限（如 `readonly` / metadata+body 按需） |
| 钉钉 | 企业数据需租户授权；与个人库物理隔离 |
| 微信/短信 | 显式 opt-in；版本与条款风险写进 connector README |
| 出站 | `outbound.enabled=false`；开启需二次确认 |

## 6. 部署草图（后续）

- Dev：本机 Python + SQLite + 本地 embeddings
- Soft prod：自家 NAS / 常开 Mac/PC（生财亦有人用高配机作 AI 中枢）
- 不推荐：把解密后的微信库同步到公开网盘

## 7. 与商业产品关系

- **LinkAI 等**：可买来验证场景，但本仓库目标是**数据与记忆自主可控**。
- **OpenClaw / LangBot**：可作渠道出站参考；本仓库先做摄入与记忆。
