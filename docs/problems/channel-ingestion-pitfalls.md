# 渠道摄入已知坑与对策

> 对应问题：「把微信、钉钉、邮件、短信等数据喂给 Agent，发现很多问题」。  
> 来源：生财实践帖 + 开源生态常识。对策面向本仓库分层架构。

---

## 微信

| 坑 | 表现 | 对策 |
|----|------|------|
| 不是 CRM / 无官方个人全量 API | 客户全在聊天里却导不出 | 本机只读解密（可选）；或人工导出；**不要**把协议机器人当数据底座 |
| 版本绑定 | 升级后解密失败 | 钉死兼容版本（如 Win 4.1.8.101 / Mac 4.1.8 build 37261）；关自动更新；文档写清 |
| 不愿降级 | 方案直接不可用 | 接受「微信插件可选」；主路径走邮件/导出 |
| DMCA / 仓库下架 | Skill 突然 404 | 自备镜像与操作笔记；不依赖单一 GitHub 地址 |
| 全量喂模型 | 噪声、贵、泄密 | 按任务窄读（群摘要、某客户跟进）；摘要后再进记忆 |
| 风控 | 破解/自动化关联封号风险 | 严格只读、自机、小号先测；默认关闭出站 |
| 「随便读我的微信」 | Agent 乱翻隐私 | 任务 prompt 收窄 + 会话白名单 + sensitivity 过滤 |

参考帖：`82255448142454542`、`45544211552415428`、`45548541854245848`。

## 钉钉 / 飞书（企业向）

| 坑 | 表现 | 对策 |
|----|------|------|
| 企业数据边界 | 个人助理误吸入公司机密 | 独立 workspace；管理员授权；字段级脱敏 |
| 开放平台权限复杂 | 申请慢、权限过大 | 最小只读 scope；先 webhook/导出 POC |
| 与个人微信混库 | 检索串话 | `channel` + `tenant` 强制隔离 |

## 邮件

| 坑 | 表现 | 对策 |
|----|------|------|
| 权限过大 | full mailbox 被滥用 | OAuth **最小权限**；只读；定期审查 token |
| HTML / 附件噪声 | 向量库被页脚、图片污染 | 抽纯文本；附件白名单；签名剥离 |
| 线程爆炸 | 同一 thread 重复 embedding | 以 `thread_id` 去重；存最新或差分摘要 |
| 把邮件当「全部人格」 | 工作邮 ≠ 真实偏好 | 与微信等分 channel 权重；事实带 source |

**本仓库 M1 优先邮件或导出文件**：合规路径清晰，适合先跑通 ingest → memory。

---

## 短信

| 坑 | 表现 | 对策 |
|----|------|------|
| 系统导出格式不一 | Android/iOS 备份难解析 | 统一到 `ChannelEvent`；先支持一种导出 |
| 验证码 / 金融短信 | 高敏 | `sensitivity=confidential`；默认不进 LLM；可只抽「有快递/有账单」类事实 |
| 运营商与隐私法 | 未同意处理 | 显式 `consent_tag` |

## 知识库 /「喂 Agent」通用坑

| 坑 | 对策 |
|----|------|
| PDF/聊天/课程一股脑扔进库（枕棠） | 先按任务整理再沉淀；知识库 ≠ 永久记忆 |
| 上下文塞满 | 检索 Top-K + 事实表，禁止每次全库 |
| 无同意、无审计 | 每条事件带 consent；记忆写入可追溯 `source_event_ids` |
| 出站误开 | `outbound.enabled=false`；写操作二次确认 |
| 夸大「已打通」 | 文档与 PR 诚实写能力边界（见 GPT_COLLAB） |

## 快速检查清单（接入新渠道前）

- [ ] 只读？出站默认关？
- [ ] 有没有官方/合规路径？若无，是否标注可选与风险？
- [ ] 脱敏规则写进 `ingest/redact.py`？
- [ ] 能否映射到 `ChannelEvent`？
- [ ] 失败时用户数据是否仍只在本地？
- [ ] README / connector 说明是否写清版本与条款风险？
